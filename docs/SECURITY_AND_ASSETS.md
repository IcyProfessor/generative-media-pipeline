# Безопасность, зависимости и ассеты

## Секреты

`.env` и локальные outputs не входят в публикацию. Сам факт копирования ключа в архив уже повод перевыпустить его, а не просто удалить файл. GitHub рекомендует сначала отозвать/заменить секрет: https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository

`check_release.py` не печатает найденные значения. По умолчанию он сканирует публичные кандидаты в рабочем дереве; `--strict` также отвергает присутствие private/generated файлов в **готовой staging-копии**. `build_release.py` экспортирует только allowlist и запускает strict check. `.gitignore` не очищает Git history, PyPI sdist или ZIP проводника.

`security.redact` убирает известные env-ключи, Bearer-токены, типичные assignments и URL-capabilities. Это защита диагностики, не повод писать полные ответы поставщиков в логи. HTTP INFO-логи отключены в CLI; локальные job JSON всё равно могут содержать URLs кандидатов и callback.

## Модель доверия

Личный/однохостовый CLI, доверенные configs/jobs/media. Не превращать без отдельной переработки в сервис загрузки неизвестных медиа. Redis доступен только локально; общая файловая система и output-root обязательны. Не обещаются distributed exactly-once, tenant isolation, ACL на каждый job, шифрование артефактов или автоматический бюджет.

Проверка HTTPS и private-literal-IP уменьшает ошибки конфигурации, но не закрывает DNS rebinding/все SSRF. Base URL выбирайте по кабинету именно вашего поставщика. Downloader не получает Authorization клиента генерации. У renderer очищены стандартные credential env-переменные, но доступ к диску не изолирован.

## Зависимости

Проверено по первичным источникам 8 октября 2026:

- MoviePy **2.2.1** объявляет `pillow>=9.2.0,<12.0`: https://raw.githubusercontent.com/Zulko/moviepy/v2.2.1/pyproject.toml
- Pillow **CVE-2026-42311 / GHSA-pwv6-vv43-88gr**: PSD OOB write, затронуты `>=10.3.0,<12.2.0`, исправлено в 12.2.0: https://github.com/python-pillow/Pillow/security/advisories/GHSA-pwv6-vv43-88gr
- Первоначальное PSD advisory прямо описывает `Image.open(formats=...)` как способ исключить PSD decoder: https://github.com/python-pillow/Pillow/security/advisories/GHSA-cfh3-3jmp-rvhc

В rc2 `Image.open` принимает только GIF/PNG/JPEG/WEBP. Проверка действует по decoder, а не только расширению: переименовать PSD/BMP в `.png` недостаточно. Это целевое снижение поверхности атаки, **не утверждение, что все уязвимости старой ветки Pillow устранены**. Другие advisories и транзитивные зависимости требуют актуального полного dependency scan.

Диапазон Pillow не расширен молча: иначе обычный resolver столкнётся с противоречием MoviePy. Не обходите его `--no-deps` в пользовательской установке. Полное решение требует совместимой обновлённой зависимости либо отдельно сопровождаемого и проверенного изменения стека. На данном этапе разрешённая область применения RC ограничена доверенными локальными ресурсами.

## Расходы и неизвестные результаты

Платные POST не повторяются автоматически. `SubmissionRejected` допустим только при достоверном отказе/до отправки. Неизвестный HTTP 5xx, malformed response, отсутствие data/task ID и общая ошибка внутри submit оставляют `submission_uncertain`. Старый job не меняет записанную историю задним числом.

Alignment имеет отдельный persisted attempt marker. Если ответ получен, но не сохранён, нужна явная новая санкция на расход. Полные raw responses не журналируются; автоматически гарантированного восстановления ответа поставщика нет.

## Медиа и лицензия

Demo: шесть геометрических персонажей и три программно нарисованных фона, исходник `scripts/build_demo.py`; не исторические GIPHY-ресурсы. Demo audio — синтетические тоны. Шрифты, пользовательская музыка/видео и чужие GIF не распространяются.

`kind=character` — имя foreground-ресурса, а не юридическая классификация. Provenance metadata не заменяет разрешения.
